Données & tests

Objectif

Séparer les règles de combat, les entités du jeu et leurs données.

Choix retenus

  • Externaliser les données du jeu. Les Pokémon, le joueur, les leaders et les maîtres sont décrits dans des CSV lus par DataLoader.
  • Tester le comportement métier. Deux cas de test couvrent les PV initiaux, les dégâts et le passage au KO avec six assertions. La présence des tests est vérifiée dans le code ; leur réussite n’est pas déduite sans exécution.

Périmètre et limites

Projet de développement distinct des missions de cybersécurité. L’examen porte sur les sources et la documentation ; le binaire du dépôt n’a pas été exécuté.

Travail réalisé

Modélisation par classes, moteur de combat, chargeur CSV et interface console.

  • Modéliser les Pokémon, attaques et dresseurs avec une approche orientée objet.
  • Séparer le chargement des données du moteur de combat et du menu.
  • Configurer la compilation C++17 avec un Makefile.
  • Fournir les diagrammes UML et des cas de test Catch.
